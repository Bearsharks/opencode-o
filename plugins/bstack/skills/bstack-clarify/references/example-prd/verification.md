# 검증 상세

## H-01 검증

지원팀 리드가 출시 다음 첫 월요일부터 연속 4주, 기준선과 같은 helpdesk의 '메모 복구' 분류로 주별 건수를 내보낸다([E-02](evidence.md#e-02-티켓-기준선)). 리드가 판정을 확정하고 지원팀 관찰 기록 `docs/support/jot-trash-post-release.md`에 집계·판정과 원본 CSV 보관 위치를 남긴다(이 PRD 바깥의 사후 기록).

**비교 규칙([사용자 답 6](request.md#이후-답변))**: 문의 접수 경로·대상이나 복구 안내 FAQ가 바뀌거나 주별 기록이 빠졌으면 판정불가; 채널명·분류 표기만 바뀌었으면 기준선 필터로 누락·중복 없이 재집계할 수 있을 때만 비교하고, 못 하면 판정불가다.

비교 가능한 4주 평균 ≤3이면 지지, >3이면 기각한다. 복원 이벤트의 존재나 건수는 판정에 쓰지 않는다.

## H-01 근거

② 지지는 비교 가능한 기간과 분류에서 지원 문의가 목표 이하였다는 뜻이다. 문의 없이 복구에 성공한 사용자와 조용히 포기한 사용자를 구별하지 못하고, 감소가 이 기능 때문이라고 단정하지 못한다. 이것이 자가 복구율과 별도로 합의한 문의 목표다.

## F-01 검증

환경: 로컬 서버, Playwright 하네스, A·B 두 계정, UTC 화면. A의 폴더 `일`에 있는 `m1`의 ID·제목·본문·수정 시각과 삭제 전 상세 URL을 기록한다. URL은 접근 시험용이며 복원 시 URL 형식을 고정하지 않는다. 삭제 조작 중 [예행한 서버 시계](evidence.md#e-04-시계-예행)를 분 경계 정각에 고정하고, 표시된 삭제 시각을 같은 분 단위로 비교한다.

| 조작 | pass |
|---|---|
| A가 `m1` 삭제 | A의 폴더 목록과 검색에서 없어지고, A 휴지통에 `m1`과 테스트 시각과 일치하는 삭제 시각이 보인다. |
| 삭제 직후 B로 로그인 | B의 목록·검색·휴지통과 `m1` 직접 URL에서 내용이 보이지 않는다. |
| A가 휴지통에서 복원 | `일`에 같은 ID·제목·본문·수정 시각을 가진 `m1`이 보이고 휴지통에서 사라진다. |
| A가 다시 `m1` 삭제 → 아직 활성인 `m2`가 담긴 `일` 삭제 → `m1` 복원 | `m2`는 폴더 삭제 시 '내 메모'로 이동하며 휴지통에 들어가지 않는다. 복원한 `m1`도 같은 ID·제목·본문·수정 시각으로 '내 메모'에 보이고 휴지통에서 사라진다. |

모두 pass여야 통과한다. 시나리오별 화면 캡처와 하네스 결과를 남긴다. API만 확인하는 것으로 대체하지 않는다.

## F-02 검증

환경: F-01과 같은 로컬 환경에서 **평상시 서비스와 같은 자동 실행 경로**를 켠다. 그 경로에 시간이 흐른 것으로 보이게 [시계 예행](evidence.md#e-04-시계-예행)을 사용한다. 고정한 삭제 시각을 서버의 휴지통 이동 시각으로 기록하고 여기에 30×24시간을 더해 만료를 계산한다. 자동 삭제 작업을 직접 호출하거나, 만료 후 첫 화면 요청·재시작으로 삭제를 유발하면 이 시험은 통과가 아니다.

영구 삭제 합격선은 자동 만료와 비우기에 같다. 활성 앱 저장소에서 메모를 찾을 수 없고, 소유자도 일반 목록·휴지통·검색·옛 상세 URL 어디에서도 메모를 조회할 수 없으며, 복원을 시도해도 메모가 돌아오지 않는다. 옛 URL의 HTTP 상태 코드 자체는 판정하지 않는다([사용자 답 4·5](request.md#이후-답변)).

| 조작 | pass |
|---|---|
| A가 `m1` 삭제. 29일째에 `m2` 삭제. `m1` 만료 1밀리초 전까지 시간을 진행 | 둘 다 휴지통과 저장소에 있고 복원할 수 있다(복원 확인은 같은 초기 상태의 별도 복제본에서). |
| 요청·재시작·수동 작업 호출 없이 시간을 `m1` 만료 +1시간까지 진행 | 화면 요청 **전** 읽기 전용 조회에서 `m1`이 없고, 이어서 영구 삭제 합격선을 모두 충족한다. 아직 미만료인 `m2`는 남는다. |
| A의 `m2`가 휴지통에 있는 상태에서 B도 별도 메모를 휴지통에 둔다. A가 비우기를 열었다가 취소 | 두 메모 모두 남는다. |
| B 세션에서 A의 휴지통을 대상으로 A가 사용할 비우기 동작을 시도한다 | B가 자신의 세션으로 시도해도 A의 휴지통과 저장소에서 `m2`가 그대로 남는다. 버튼이 보이지 않는다는 확인만으로는 통과하지 않는다. |
| A가 다시 비우기를 열고 확인 | 완료 응답 시 A 휴지통은 비고 `m2`가 영구 삭제 합격선을 모두 충족한다. B의 메모는 남는다. |

모두 pass여야 통과한다. 가상 시간과 서비스/요청 타임라인, DB 관찰 출력, 화면 캡처를 남긴다. 운영 환경의 가동 중단이나 실제 부하에서의 보장은 이 예행과 별개다.
