# Jot 휴지통

[요청과 결정 원문](request.md)

## 목표

Jot 사용자가 실수로 지운 메모를 스스로 복구할 수 있게 해 [지원팀 복구 문의를 줄인다](request.md#요청-원문).

## 범위

- 포함: 삭제한 메모의 휴지통 이동, 메모 복원, 만료 후 자동 영구 삭제, 계정별 휴지통 비우기.
- 제외: **폴더 자체의 복원** — [사용자 답 1](request.md#이후-답변). 복원 대상 메모는 원래 폴더의 존부와 관계없이 범위 안이다. **운영 백업 소거와 폴더 삭제의 기존 이동 정책 변경** — [사용자 답 4](request.md#이후-답변).
- 영향받는 기존 계약: 폴더 삭제 시 메모를 옮기는 기존 정책 — 유지, [사용자 답 4](request.md#이후-답변).

## 성공 판정표

| ID | 성공 정의 | 검증 | 근거 |
|---|---|---|---|
| H-01 | 출시 뒤 Jot '메모 복구' 티켓 주 평균 12.5건 → 3건 이하 | 지원팀 리드가 4주 CSV를 기준선과 [같은 기준으로 비교](verification.md#h-01-검증)할 수 있을 때만 지지·기각을 판정한다. 예행 [E-02](evidence.md#e-02-티켓-기준선) | ① 사용자 「출시 다음 첫 월요일부터 4주간 '메모 복구' 문의가 주 평균 3건 이하면 성공이야.」 [답 2·6](request.md#이후-답변), [기준선](evidence.md#e-02-티켓-기준선) ② 비교 가능한 문의 건수의 변화만 보장하며 자가 복구율이나 인과는 [판정하지 않는다](verification.md#h-01-근거). |
| F-01 (→H-01) | 지운 메모는 목록·검색에서 사라지고 휴지통에 삭제 시각과 함께 보인다. 원래 폴더 또는 없는 경우 '내 메모'에 같은 ID·제목·본문·수정 시각으로 복원한다. 다른 계정에 노출하지 않는다. 기존 폴더 삭제는 활성 메모를 '내 메모'로 옮긴다. | 두 계정과 폴더 상태를 바꿔 [목록·검색·휴지통·복원 결과](verification.md#f-01-검증)를 비교한다. 예행 [E-03](evidence.md#e-03-관찰-표면) | ① 사용자 「메모의 ID, 제목, 본문, 수정 시각은 유지해.」 [답 1](request.md#답-1--원래-폴더가-없어졌다면-어디에-복원하나요)의 위치·노출 조건과 [답 4](request.md#이후-답변)의 기존 폴더 삭제 동작을 보존한다. ② 이 두 계정과 폴더 상태에서 숨김·복원·격리를 확인한다. 전체 권한 조합을 보장하지는 않는다. |
| F-02 (→H-01) | 서버의 휴지통 이동 시각 + 30×24시간이 만료다. 그 전에는 자동 삭제하지 않고 이후 1시간 안에 조작 없이 영구 삭제한다. 영구 삭제는 활성 앱 저장소에서 제거해 앱의 조회·복원을 막는 것이다(HTTP 상태 코드 무관). 비우기는 본인 휴지통만 확인 즉시 같은 방식으로 지우며 취소나 다른 계정의 비우기 시도는 대상 휴지통을 바꾸지 않는다. | [정상 백그라운드 실행을 가상 시간으로 관찰](verification.md#f-02-검증)하고 비우기 확인·취소와 다른 계정의 비우기 시도를 확인한다. 예행 [E-03](evidence.md#e-03-관찰-표면), [E-04](evidence.md#e-04-시계-예행) | ① 사용자 「그 시점부터 1시간 안에는 사용자가 아무것도 안 해도 영구 삭제되어야 해.」 [답 3–5](request.md#이후-답변)의 보관 약속·삭제 범위·권한을 따른다. ② 수동 전용 만료나 다른 계정의 휴지통을 지우는 동작을 탈락시킨다. 증거의 범위는 테스트 계정의 활성 저장소와 조회·복원 표면이다. |

## 가정과 미결정

| ID | 내용 | 판정을 바꾸지 않는 이유 |
|---|---|---|
| A-01 | 측정 기간의 분류 기준·채널·FAQ는 비교 가능할 것으로 본다. | 그렇지 않으면 H-01의 판정불가 규칙을 적용한다. |
| A-02 | 만료 스케줄링 방식은 구현자에게 맡긴다. | F-02의 보관 하한, 1시간 상한과 무조작 조건은 고정이다. |
