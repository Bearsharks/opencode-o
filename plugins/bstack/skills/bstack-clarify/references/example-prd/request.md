# 요청 원문

> 실수로 Jot 메모를 지운 사용자가 지원팀에 복구를 요청하는 문의가 너무 많아. 휴지통을 만들어 줘. 지운 메모는 30일 동안 보관하고 그 뒤엔 자동으로 영구 삭제해. 휴지통 비우기 버튼도 있어야 해. 지원 티켓이 확실히 줄었으면 좋겠다. 지난달 티켓은 `docs/support/2026-10-tickets.csv`에 있어.

## 이후 답변

### 답 1 — 원래 폴더가 없어졌다면 어디에 복원하나요?

> '내 메모'(최상위)로 복원. 폴더 자체 복원은 이번에 안 해. 메모의 ID, 제목, 본문, 수정 시각은 유지해. 삭제 중에는 일반 목록과 검색에 나오면 안 되고 휴지통에서는 삭제 시각을 보여줘. 다른 계정에 노출되면 안 돼.

### 답 2 — 티켓 목표와 관찰 기간은요?

> 출시 다음 첫 월요일부터 4주간 '메모 복구' 문의가 주 평균 3건 이하면 성공이야. 분류 기준이나 지원 채널·FAQ가 바뀌어 같은 기준으로 비교할 수 없다면 판정을 보류해. 실제 자가 복구율까지 이번에 요구하는 건 아니야.

### 답 3 — 자동 삭제 경계와 비우기 확인은요?

> 메모가 휴지통으로 이동한 서버 시각부터 30×24시간을 채우기 전에 자동 삭제하면 안 돼. 그 시점부터 1시간 안에는 사용자가 아무것도 안 해도 영구 삭제되어야 해. 비우기는 확인한 계정의 휴지통만 즉시 삭제하고, 취소하면 아무것도 삭제하지 마.

### 답 4 — 영구 삭제가 어디까지인가요? 폴더를 지울 때의 기존 정책도 바꾸나요?

> 영구 삭제는 활성 앱 저장소에서 메모가 없어지고 앱 어디에서도 조회·복원할 수 없다는 뜻이야. 운영 백업 소거는 이번 범위가 아니고 기존 백업 정책 그대로야. 폴더 자체를 삭제하면 아직 지우지 않은 메모를 '내 메모'로 이동시키는 현재 동작도 그대로 둬.

### 답 5 — 삭제 뒤 옛 주소의 응답과 계정 간 비우기 권한은요?

> 자동 삭제든 비우기든 앱에서 메모를 조회하거나 복원할 수 없으면 돼. 옛 주소의 HTTP 상태 코드는 정하지 않아. 다른 계정은 내 휴지통을 비울 수 없어야 해.

### 답 6 — 측정 중 채널·FAQ·분류가 바뀌면 언제 비교하나요?

> 문의 접수 경로·대상이 바뀌거나 복구 안내 FAQ가 바뀌면 판정불가야. 채널명·분류 표기만 달라졌다면 기준선 필터로 누락이나 중복 없이 다시 집계할 수 있을 때만 비교해.

## 예시 안내

가상 사용자와 대화한 원문 형식의 예시다. 증거 파일의 예행 관찰도 가상이며, 검수 run 기록은 이 PRD에 포함하지 않는다.
