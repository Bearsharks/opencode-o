# 어떤 공백이 남았는가?

맞는 행 하나를 골라 `${CLAUDE_PLUGIN_ROOT}/skills/` 아래 표에 적힌 파일을 **Read**한다. 자동 발동을 기다리지 않는다. 원본의 작업 지시는 필요한 만큼 작업자 brief로 바꾸고 결과를 해당 셀에 돌려놓는다. 기획 범위를 넘어 코드·배포·ADR을 납품하지 않는다.

| 판단이 갈리는 곳 | 읽을 경로 | 작업자에게 줄 단서 → 셀에 돌려놓을 것 |
|---|---|---|
| 어떤 사용자 문제가 풀려야 하는지 모름 | `product-lens/SKILL.md` | 사용자 사례와 현재 우회책 → H/성공 정의와 왜 중요한지 |
| 깨진 경험도 통과하거나 정상 대안이 탈락 | `acceptance-criteria/SKILL.md` | 행동·결과·보존 제약 → 양방향 반례를 가르는 F/검증 |
| 자료가 입증하는 것과 권고가 섞임 | `research-ops/SKILL.md` | 기존 자료·날짜 → 사실/추론 구분과 판단을 바꿀 추가 증거, H 또는 F/근거 |
| 같은 사용자 장면의 실현 가능성이나 관찰 수단을 비교해야 함 | `bstack-mode/playbooks/prototype.md` | 판별 질문 → 격리된 최소 비교의 관찰과 선택 이유. 장면을 바꾸는 새 규칙은 실험으로 정하기 전에 사용자에게 묻는다. |
| 같은 문제에 대한 판정안 여러 개가 필요 | `arena/SKILL.md` | 동일 원문·사전 평가 기준 → 독립 후보 비교와 셀 선택 이유 |
| 정책·데이터·실제 표면을 독립 조사해야 함 | `swarm/SKILL.md` | 범위별 확인 대상 → 취합된 관찰과 여전히 남은 공백 |
| 현재 검증에서 깨진 동작이 살아남는지 의심 | `interrogate/SKILL.md` | 의도·기존 검증·표면 → 재현된 반례, 해당 검증/근거 수정 |
| 숫자가 효과 대신 캐시나 잡음을 반영할 수 있음 | `principle-explain-the-number/SKILL.md` | 기준선·변동·결정 경계 → 실제 측정 대상과 신뢰 가능한 범위 |

반례 없음은 승인과 다르며, 선호를 투표로 대신 정하지 않는다.
