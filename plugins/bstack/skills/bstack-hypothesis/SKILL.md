# 제품 가설

이 요청이 제품에 기여하는지 확인하는 단계다. 기여한다면 그것을 무엇으로 판정할지 정한다. 결과는 PRD 폴더의 `hypothesis.md` 하나이고, 사용자가 확인하면 끝난다. 폴더는 [PRD 폴더 규칙](../bstack-feature/SKILL.md#진행)대로 열고, 기능 PRD도 같은 폴더를 이어 쓴다. 독립 검수는 없다. 이 단계는 선택이며, 기능을 어떻게 만들지는 여기서 정하지 않는다.

## 절차

1. **문제와 증거를 찾는다.** 누가 어떤 문제를 얼마나 겪는지 본다. 레포나 자료에서 찾을 수 있는 것은 `bstack-run run --role explore`에 맡긴다. 그다음 사용자에게 묻는다. "이 문제가 실재하고 풀 가치가 있다는 증거가 있나요? 사용자 발언, 지원 티켓, 지표, 관찰한 행동, 실패한 우회책 같은 것이요." 증거가 없으면 문제 절에 `가정 — <사용자 조사 | 데이터 분석 | 프로토타입>으로 확인 필요`라고 남긴다.
2. **기여 사슬을 그린다.** 요청 → 사용자 행동 변화 → 제품 결과의 순서로 그린다. 고리마다 근거를 달고, 근거가 없으면 가정이라고 표시한다.
   - 사슬을 그릴 수 없거나 기여를 잴 지표를 정할 수 없으면 버림 후보로 사용자에게 보인다. 버릴지는 사용자가 정한다. 요청 전체를 버리면 `git mv .bstack/<name> .bstack/archive/<name>`으로 보관한다.
   - 기여하지 않아도 사용자가 원하는 요구는 "가설 없이 유지"로 적는다.
3. **가설과 지표를 정한다.** 목표치와 판정 규칙은 사용자가 정한다. 에이전트는 기준선과 선택지를 낸다.
4. **사용자에게 확인받는다.** 문서를 보여 주고 "이렇게 할까요?"라고 묻는다. 확인되면 끝이다. 기능 PRD가 이어지면 [bstack-feature](../bstack-feature/SKILL.md)에 이 문서를 넘긴다.

## hypothesis.md

```markdown
# <name> — 제품 가설

## 문제
<누가 어떤 문제를 얼마나 겪는가, 증거와 출처>

## 기여 사슬
<요청 → 사용자 행동 변화 → 제품 결과. 고리마다 근거 또는 "가정">
- 버림: <요구와 이유, 사용자 결정 원문> (없으면 생략)
- 가설 없이 유지: <요구와 사용자 결정 원문> (없으면 생략)

## 가설
| ID | 가설 | 지표와 판정 | 근거 |
|---|---|---|---|
| H-01 | <누구에게 어떤 결과가 얼마나 바뀌는가> | <어디서 무엇을 재는가, 기준선 → 목표, 지지/기각/판정불가 규칙, 판정 시점과 판정자> | <왜 이 결과가 제품의 성공인가, 왜 이 지표가 그 기여를 재는가> |
```

- 지표는 사슬의 결과 쪽에 둔다. 기능 사용량이나 출시 여부는 기여를 재지 않는다.
- 근거에서 사용자 원문은 `사용자 「원문 발췌」`로, 에이전트 판단은 `에이전트: 이유`로 시작한다.
- 가설은 하나가 기본이다. 서로 다른 결과를 노릴 때만 나눈다.
- 측정의 정밀도는 판정이 갈리는 수준이면 충분하다.
