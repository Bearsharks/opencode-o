# 작업 문서와 검수

기획이 확정되면 구현 전에 `acceptance-criteria` 스킬을 사용한다. 제품 레포의 작업 문서 한 곳에서 현재 기획·결정·완료조건과 하단 변경이력을 관리한다. 기준이 확정되어 커밋되면 해당 워크트리의 `pstack.taskDoc`에 경로를 한 번 기록한다. 관련 세션에는 경로 한 줄이 전달된다. 임시 조사나 독립 작업에 다른 워크트리의 기준을 가져오지 않는다.

구현·위임에서는 현재 본문을 읽고, Shipping은 PR 본문의 Task-Doc 경로를 검수 대상 head에서 읽는다. 구현 방법·관찰 결과는 기준을 대체하지 않는다. 검수 지적은 Shipping이 기준·관찰·판정으로 모은다. 재작업 시 구현자는 같은 문서와 검수 댓글을 읽는다. 같은 결과로 끝날 추가 검증은 생략한다.
