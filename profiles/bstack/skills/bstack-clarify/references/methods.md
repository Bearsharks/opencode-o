# 결정에 맞는 메서드 선택

직접 읽거나 관찰하면 답이 나오는 문제에는 별도 메서드가 필요 없다. 아래는 순서가 아니라 선택지다. 필요한 행의 스킬만 로드하고 결과를 PRD에 반영한다.

| 필요한 결정 또는 증거 | 메서드 | PRD에 가져올 것 |
|---|---|---|
| 사용자에게 실제로 중요한 결과 | `bstack-product-lens` | 기능명 대신 사용자 문제·가설과 출처 |
| 서로 다르게 쓰는 용어·정책 | `bstack-context-decisions` | 결정권자가 정한 의미와 적용 범위 |
| 기능 판정이 거짓 통과를 허용하는지 | `bstack-acceptance` | 관찰 가능한 합격·불합격 경계 |
| 사실·결정·추론이 혼재한 자료 | `bstack-research-ops` | 인정할 출처와 남은 불확실성 |
| 비교 관찰로 구별할 대안 | `bstack-prototype` | 최소 실험의 조건·실제 결과·한계 |
| 별개 출처에서 구해야 하는 정보 | `bstack-swarm` | 조사 범위별 증거와 공백 |
| 공통 기준으로 골라야 할 후보 | `bstack-arena` | 후보 간 차이와 선택 이유 |
| 실패를 실제로 재현해야 하는 주장 | `bstack-interrogate` | 재현 조건·관찰 또는 미재현 |
| 수치가 실제 목표를 측정하는지 | `bstack-explain-the-number` | 효과·잡음·대리 신호 및 보장 범위 |
